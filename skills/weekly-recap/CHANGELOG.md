# 更新日志

weekly-recap 各版本的主要变化，最新的在最上面。更新方法见仓库 README 的「更新」一节。

## 0.7.4 · 2026-10-19

- 「其他」里的每一项都要写清是哪个功能、在什么情况下、出了什么问题，比如「用 http 地址访问时创建故事报错」，不再写「非 HTTPS 页面请求出错」这类只有自己看得懂的缩写；说不清楚的就不写。
- 纯文本转换支持「其他（已发布）：A；B」这种带状态的写法，也会拆成多行。

## 0.7.3 · 2026-10-19

- 严重问题不再埋进「其他」：会让下单、支付、登录失败、页面或列表整体出错、数据丢失或错误，或影响购买和埋点数据的修复，都单独成条，写清原因和解决。按提交说明里的实际影响判断，不看标题写得多轻。
- 不再用「体验优化」「细节优化」这类笼统名字把不相关的改动打包，每条按实际内容命名。
- 下周计划只有从进度推出来的跟进项时，周报下面会提示可以补充自己的计划。

## 0.7.2 · 2026-10-19

- 去掉「技术沉淀」一节：抽公共方法、改配置这类小改动不再单独列，修了问题的放进问题修复的「其他」，其余不写。
- 「团队贡献」门槛提高：只写别人真正用得上的东西，比如共享组件、团队工具或脚本、能拦住一类错误的 CI 或发布检查、规范和文档，以及你补充的帮同事排查、分享等。
- 经验不再单列，只在不显而易见、对团队有用时，作为难点问题下面的一条「经验」。

## 0.7.1 · 2026-10-19

- 本周工作重新按项目分区，项目下面再分功能交付、问题修复、技术沉淀，条目里不再重复写项目名；纯文本用「一、项目」「（一）功能交付」「1. 条目」三级。
- 进度只用三种说法：合入测试分支为「已提测」，合入 master 为「已发布」，其余为「开发中」，不再写「已合入 master」。

## 0.7.0 · 2026-10-19

- 周报改为「本周工作」和「下周计划」两部分。本周工作按功能交付、问题修复、技术沉淀、团队贡献整理；有上一份周报时，先对照它的下周计划写出完成情况。
- 写法更真实朴素：不写代码行数、测试数量这类工作量数字，不用夸大的词，不加价值标签；功能里不写实现细节，有难度的问题写清原因和解法。
- 收集前自动拉取远端（只更新远程分支记录，不改本地分支和文件，不弹密码），网页上合并的也能算进来；进度按提交实际在哪个远程分支上判断（已合入 master、已预发布、已提测、开发中），分支名可在配置里自定义。
- 提问增加第三项「下周计划和其他补充」，可不填，默认根据进行中的工作拟定。
- 在 Codex 这类只能单选的提问框里，仓库选项改为常用组合：最近有提交的项目、全部项目、只要当前项目。
- 新增 `store.py plan`，读取上一份周报的下周计划。

## 0.6.1 · 2026-10-15

- 每次说「写周报」都会重新问时间和仓库，同一个对话里也不沿用上一次的回答。
- 在「其他」里填新仓库路径后，它会加入选项，让你和其他仓库一起再勾选一次。可以一次填多个，也可以分几次添加。
- 当前目录已经被记住时，在仓库选项里只出现一次。

## 0.6.0 · 2026-10-15

- 周报文件按时间范围命名，整周和自定义范围统一：`~/.weekly-recap/2026/26.10.12-26.10.18.md`。以前的 `week-42.md` 等文件仍能读到，并会自动改成新名字。
- 生成后以带复制按钮的纯文本代码框显示结果，不再重复显示渲染后的 Markdown。

## 0.5.0 · 2026-10-15

- 保存后自动把纯文本版复制到剪贴板：分区用「一、」、条目用「1.」、子项用「-」，【】代替加粗，粘贴进表格或聊天也不会乱。
- 「其他」里的小改动、难点的原因和解决，都各占一行。
- 新增 `store.py text`，可以把已保存的周报重新转成纯文本并复制。

## 0.4.0 · 2026-10-15

- 周报更精简：去掉和正文重复的「本周重点」，工作按重要程度排序，只给最重要的 1–3 项加粗。
- 小改动统一收进「其他」，不再为了篇幅直接删掉。
- 默认不带链接；需要时说一句「周报附上 PR 链接」即可。
- 攻克点和踩坑合并为「难点与经验」，只写真正有难度、原因明确的事，没有就不写。
- 能从分支看出时，标注「已提测」「已合入 master」等状态。

## 0.3.0 · 2026-10-15

- 只问两件事：时间范围和仓库，选完直接生成并保存，中间不再确认日期、不再问攻克点、不再问是否覆盖。
- 选过的仓库自动记住；名字重复时自动改成「上级目录/目录名」。
- 仓库选项按你最近一次提交的时间排序。
- 新增单元测试，并在 CI 中运行。

## 0.2.1 · 2026-10-15

- 没有提交的仓库直接略过；所有仓库都没有提交时，提示一次就结束，不再追问。
- 插件卡片显示作者和显示名。
- README 补充命令行更新和开启自动更新的方法。

## 0.2.0 · 2026-10-15

- 日期按电脑的本地时区计算，范围从起始日 00:00:00 到结束日 23:59:59。
- 收集提交前不再询问是否 fetch。
- 修复：用路径选择已记住的仓库时保留它的名字和链接配置；识别不带规范前缀的修复提交；`--output` 默认写入只有本人可读的临时文件；自建 Git 服务带端口时链接不再丢端口。

## 0.1.0 · 2026-10-15

- 首个版本：从自己在多个仓库的 git 提交生成周报，附带提交和 PR 链接、难点线索，保存在本地，支持 Claude Code 插件市场和 Codex 安装。
