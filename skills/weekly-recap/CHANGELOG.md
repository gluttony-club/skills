# 更新日志

weekly-recap 各版本的主要变化，最新的在最上面。更新方法见仓库 README 的「更新」一节。

## 0.6.1 · 2026-10-15

- 每次说「写周报」都会重新问时间和仓库，同一个对话里也不沿用上一次的回答。
- 在「其他」里填新仓库路径后，它会加入选项，让你和其他仓库一起再勾选一次。可以一次填多个，也可以分几次添加。
- 当前目录已经被记住时，在仓库选项里只出现一次。

## 0.6.0 · 2026-10-15

- 周报文件按时间范围命名，整周和自定义范围统一：`~/.weekly-recap/2026/26.10.12-26.10.18.md`。以前的 `week-42.md` 等文件仍能读到，并会自动改成新名字。
- 生成后以带复制按钮的纯文本代码框显示结果，不再重复显示渲染后的 Markdown。

## 0.5.0 · 2026-10-15

- 保存后自动把纯文本版复制到剪贴板：分区用「一、」、条目用「1.」、子项用「-」，【】代替加粗，粘贴进表格或聊天也不会乱。
- 「其他」里的小改动、难点的原因和解决，都各占一行。
- 新增 `store.py text`，可以把已保存的周报重新转成纯文本并复制。

## 0.4.0 · 2026-10-15

- 周报更精简：去掉和正文重复的「本周重点」，工作按重要程度排序，只给最重要的 1–3 项加粗。
- 小改动统一收进「其他」，不再为了篇幅直接删掉。
- 默认不带链接；需要时说一句「周报附上 PR 链接」即可。
- 攻克点和踩坑合并为「难点与经验」，只写真正有难度、原因明确的事，没有就不写。
- 能从分支看出时，标注「已提测」「已合入 master」等状态。

## 0.3.0 · 2026-10-15

- 只问两件事：时间范围和仓库，选完直接生成并保存，中间不再确认日期、不再问攻克点、不再问是否覆盖。
- 选过的仓库自动记住；名字重复时自动改成「上级目录/目录名」。
- 仓库选项按你最近一次提交的时间排序。
- 新增单元测试，并在 CI 中运行。

## 0.2.1 · 2026-10-15

- 没有提交的仓库直接略过；所有仓库都没有提交时，提示一次就结束，不再追问。
- 插件卡片显示作者和显示名。
- README 补充命令行更新和开启自动更新的方法。

## 0.2.0 · 2026-10-15

- 日期按电脑的本地时区计算，范围从起始日 00:00:00 到结束日 23:59:59。
- 收集提交前不再询问是否 fetch。
- 修复：用路径选择已记住的仓库时保留它的名字和链接配置；识别不带规范前缀的修复提交；`--output` 默认写入只有本人可读的临时文件；自建 Git 服务带端口时链接不再丢端口。

## 0.1.0 · 2026-10-15

- 首个版本：从自己在多个仓库的 git 提交生成周报，附带提交和 PR 链接、难点线索，保存在本地，支持 Claude Code 插件市场和 Codex 安装。
